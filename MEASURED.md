# What turned out to be true

Every claim this project makes, with the test that produced the number. The ones that contradict
what [IDEAS.md](IDEAS.md) predicted are marked -- the predictions are left standing rather than
quietly edited, because a design note that only ever agrees with the result is not a design note.

Read [STATUS.md](STATUS.md) for what is built and what is not, and [IDEAS.md](IDEAS.md) for why
any of it was tried.


Measured, with the test that produced each number. The ones that contradict what
[IDEAS.md](IDEAS.md) expected are marked.

| | |
|---|---|
| Ordering without sorting is good enough | flicker from approximate order is ~1/3 of the camera's own frame-to-frame change, at every percentile including the single worst pixel (`py/stage0_motion.py`) |
| The inversion rate is a bad predictor | 14.7% of weighted pairs are inverted and the images are still hard to tell apart; the pair rate and the image error are only loosely related (`py/stage0.py`) |
| **Against IDEAS.md:** inversions are not hidden by opacity | visible-weighted 16.0% ≥ opacity-weighted 15.5% (`py/stage0_detail.py`) |
| **Against IDEAS.md:** hierarchical order is not more stable in time | it is ~5× *less* stable by pair-churn (`py/stage0_detail.py`) |
| **Against IDEAS.md:** front-to-back early-out is a net loss here | skips 6% of nodes and triples the per-node cost, because the canopy is only ~2× overdrawn at this level of detail. Kept behind a flag, off |
| Re-rooting works, and is necessary | depth 52, 11 orders of magnitude; a round trip through world coordinates is exact to one float64 ulp *in world units*, which at that depth is a ten-thousandth of a local one (`web/tests/reroot.mjs`) |
| The cross-fade earns its place | ~30× fewer splats whose opacity jumps visibly in a frame, versus a hard cut (`web/tests/pop.mjs`) |
| The level of detail is faithful | 26–44 dB against a fully-expanded ground truth at 2–12× fewer splats; sparse sharp structures are the hard case, because a Gaussian cannot represent a sharp-edged void (`web/tests/fidelity.mjs`) |
| The murky canopy is the tree, not the approximation | blob opacity was swept against ground truth and 0.95 won; the 900k-splat ground truth is just as murky (`/tmp` sweep, recorded in STATUS.md) |
| Ordered expansion survives the move to the GPU | the WGSL kernel reproduces the CPU expansion with 0 wrong draw slots out of 114,687 (`web/tests/gpu_transcribe.mjs`) |
| Similarity maps make the eigensolver unnecessary | the foliage disc's principal axis is the accumulated affine's third column, normalised — equal to the Jacobi solve to 6e-8 |
| **Against expectation:** a crowd does not make the draw order worse | 7.68% mean weighted inversion rate with 25–38 objects in view vs 9.60% for the seven-object ring in the same run, and 0.015/255 image difference from an exact global sort — the cells' guaranteed disjoint bounding spheres are what buy it (`web/tests/order_field.mjs`) |
| An endless field costs no more than the fixed seven | 41.3 vs 42.9 ms/frame on the CPU for ~30 objects vs 7, and 0 blank frames vs 32; the per-node frustum and occlusion culling already made off-screen objects free (`web/tests/tour.mjs`) |
| **Against expectation:** a shared attractor is not a shared appearance | eight pooled shapes serve hundreds of cells without visible repetition, because each cell supplies its own root hash and the address-hashed jitter makes that a different realisation of the same map set |
| The frame-time spike was the collector, not the arithmetic | a "rebuild" measured at 33 ms against a per-rebuild p99 of 2.06 ms over every morph pair; `frames()`, `rootFrame()` and `retarget()` were allocating per object per frame. Allocation-free: 1.99 → 1.14 ms/frame (`web/tests/tour.mjs`) |
| Jitter can morph, and the table it needed was 4× too big | the rotation is assembled during `reparam` from a cached axis instead of baked at construction, bit-exact against the shared reference over 193,536 entries; the table went 4096 → 1024 and a rebuild 1.388 → 0.44 ms, which is what pays for morphing continuously. 256 entries (×127 reuse) still show no visible repetition (`web/tests/jitterbits.mjs`) |
| A clamp added for safety is a discontinuity added on purpose | every break in the morph's smoothness came from a guard, never from the spline: a scale clamp whose bounds changed at each waypoint, an `omega` clamp that every crystalline set sat exactly on, and a `Math.max(1e-9, sig0)` floor that was hiding `sig0` reaching **−0.021** — a negative variance. Reparameterising instead (log space; the square of a splined square root) removed all three and the need for any guard (`web/tests/breath.mjs`) |
| Exactly 180° apart has no short way round | `roll` steps exactly 180° twice in the loop, and the textbook formula resolves the tie identically in both directions, so the tangents disagreed across the loop's wrap — a visible lurch twice a cycle. The tie-break must also depend only on the residue, because the unwrap chain hands the same angle back shifted by 360 |
| The morph is now C¹, and the breath pays for itself | 0.053% velocity change across a waypoint against 44.5% for the old hold-then-crossfade chain; quantising by distance travelled rather than time means the slow, legible moments cost 0.46 rebuilds/frame against 1.48 while quick (`web/tests/breath.mjs`) |
| "Not based on a tree" was content, not architecture | `omega` is the trunk's mass fraction and had never been varied — all seven sets shipped between 0.15 and 0.38 with identical jitter. A Sierpinski tetrahedron is four similarity maps at `omega = 0` and needed no engine change; four non-tree sets were added this way (`web/tests/catalogue.mjs`) |
| A cosmetic-looking list order was part of a geometric proof | `REACH_MAX` bounds every object's extent and the draw order rests on it. An ordering that put the two highest-contraction sets adjacent sent the spline's overshoot to 5.12 against a bound of 3.75 — enough to intersect neighbours and cut a seam through both — because R grows like 1/(1 − contraction). Interleaving brought it to 3.92 |
| A hierarchy makes the separation proof shorter, not longer | a cell either holds an object or subdivides, never both, so every pair of object-holding cells is disjoint and the objects cannot intersect whatever levels they are at. 983,142 pair-tests over 66,818 objects, 619,519 of them cross-level: 0 intersecting (`web/tests/field.mjs`) |
| **Against expectation:** clustering did not hurt the draw order | 7.52% mean weighted inversions with clusters against 8.07% for the flat field, and 0 blank frames on the tour despite 51% of root cells now being empty voids |
| Motion is free, because the proof bounds the envelope | objects drift, breathe and turn continuously; the drift amplitude is drawn from what is *left* after the static offset and the size breathes *downward* from the cap, so the envelope is the sphere the static field already fitted inside the cell. 1,556,516 pair-tests across 481 instants over 240 s: 0 intersecting |
| **Against its own measurement:** the "quarter of the flight is featureless" number was partly the probe | `legible.mjs` called a frame bright if its pixels were over an absolute 8/255, and the flat clear colour it draws on is 10–16 after gamma — so an empty frame scored `lit = 1.00` and 99.6% of crossing frames were filed as a fog bank. Counted against the background instead, the flight as it stood was 29.6% washed out *and* 22.9% nearly empty, which are opposite faults wanting opposite fixes (`web/tests/legible.mjs`) |
| The dive had no brakes, and nothing noticed for a long time | `cruise()` scales its step by how much of the heading points at the target; `dive()` never did, so a camera facing away closed a fraction of a distance its own motion was increasing — a bare dive reaches 3e14 local units. `tests/reroot.mjs` had been printing `depth reached 0` and passing, because both its assertions are on errors and errors are smallest when nothing happens. With the guard: frames spent inside the attractor 0.28 → 0.95, median depth reached 3 → 24 over 10 sets × 6 seeds |
| Aiming at edges beats aiming at mass | scoring children by how far out of the node they sit and aiming half a child-radius out along that direction took dive frames from 37.4% washed out to 27.3% over the same 200 s flight — while flying 1.7× slower and ten levels deeper. Overall emptiness 22.9% → 11.8% (`tests/legible.mjs`) |
| **Against the instruction that asked for it:** deeper costs legibility | washed-out frames sit at a mean depth of 34 against 13 for legible ones. The dive is better at every depth now, but depth itself is still the strongest predictor of a wash, and the climb back out — which spends most of its frames deep — is the worst stretch of the flight at 78% |
| Curving the path as well as the aim made it worse | `edgeSlide` at 0.30 took a dive-only flight from 30.0% washed out to 33.7%. Kept in the code, switched off, with the number in the comment |
| Half the frame rate was a different flight | the steering followers integrated 1/60 s per call whatever the frame took, and the forward step closed a bare fraction of the remaining distance, which does not compose (0.95² ≠ 0.90). Fixed, 30fps and 60fps now agree to 0.26° after half a second — and only the near term is assertable: perturb the speed by one part in a million and the heading is 60° away three seconds later (`tests/pilot.mjs`) |
| The browser never flew the flight the tests measured | `frameFlight` passed `flySpeed` (0.02) into `pilot.step()`, overriding `Autopilot.speed` (0.0105), which every headless test used |
| A star field can be band-limited, the same way the splats are | floored at 1.3 px of the real viewport, the sky answers a 4× bigger turn with a 3.9× bigger change; unfloored it is already at its worst-pixel ceiling for a quarter-pixel turn and does not grow, which is what crawling is (`tests/space.mjs`) |
| Smaller morph steps cost less, not more | the step per rebuild went from a mean of 1/171 of a segment to 1/463 and a p99 of 1/71 to 1/194, and the pool asks for *fewer* rebuilds because the quantum is distance travelled: 0.58/frame at 0.44 ms against a 1.5 ms budget (`tests/breath.mjs`) |
| Smaller steps are not a smoother animation | the morph was C¹ and never stalling *as a path*, and what reached the screen was that path sampled 18–26 times a second and held between samples: **61% of slot-frames drew exactly the frame before**. The table the traversal reads is the only thing a viewer sees, and nothing measured it (`tests/breath.mjs` §5) |
| Interpolate in the read, not into a third table | the premultiplied child table is linear in the maps, so `lerp(J@A0, J@A1) = J@lerp(A0, A1)`. Materialising that blend per frame was correct and unaffordable — 288 KB of writes that pushed the frame p99 from 103 to 564 ms by evicting the cache the expansion works in. Lerping the two tables *as the traversal indexes them* costs **+3.8%** on one 140k-splat frame and takes the drawn shape from 25.6 Hz to **59.7 Hz** on a 60 Hz display, 0.7% of slot-frames still (`tests/breath.mjs`) |
| A switch may change the motion, never the frame it is clicked on | the blend extrapolates, so the drawn shape sits past the newest build; turning interpolation off by collapsing the table pair moved **8 slots of 8**. Folding the live blend into the newest build first makes the switch invisible: snapshots of the drawn table either side of every flip, **0 slots differ**, across both switches in both directions (`tests/toggles.mjs`) |
| The panel's two morph rates are counted, not inferred | a slot-frame counts as moved if that slot was rebuilt or its blend fraction changed -- the event `tests/breath.mjs` counts offline. At the demo's settings: **57.7 drawn changes/s from 2.7 rebuilds/s** with interpolation, **7.0 from 7.0** without, **0 and 0** with the morph held; each within 2 Hz of the slot-frames counted independently (`tests/toggles.mjs`) |
| **Against the design note that called the way back in safe:** a reconciled table is not a reconciled shape | the small derived state -- moments, bounding radius, child scales, the LOD metric, the map translations -- is snapshotted under the same flag that interpolates it, so while interpolation was off it stopped being taken; switching back on collapsed the pair onto a snapshot a build old and scattered it over a table that was current. **8 slots of 8** jumped at the click, `R` by up to **1.37** and σ₀ by **8×**, with the drawn table perfectly correct -- and only that slot's next rebuild put it right, which with the morph held is never. `setInterp` re-gathers the live state on the way in, and the test snapshots the moments, radius, scales and translations across every flip as well as the table (`tests/toggles.mjs`) |
| **The parameter was right and the picture still jumped** | every other measurement of the morph is of a parameter or a table entry, and a viewer sees neither: a splat's position is the table composed down an address times an interpolated centre plus interpolated translations, and a product of blends is not the blend of a product. Measured as positions, against an exact build at the same parameter, over 10,552 slot-frames: **17 frames stepped more than 8x the true motion, up to 36x**, 7 moved against the morph, worst position error **9.6e-3 of the object's radius**. Three causes, all invisible in the quantity each was written in: the build was made at the parameter the morph had already reached (so the fraction reset to 1 every rebuild and the hand-over sat at the tip of the extrapolation), a table resize threw the blend's pair away (one shape held for a whole interval, 150 times a minute), and the resize also forced a rebuild a quarter of a quantum early (a fraction of -3.06, clamped, and a clamp is a freeze). Now **0 jumps, 0 reversals**, worst error **8.2e-5**, and the drawn motion equals the true motion to 1.000x at p50, p90 and p99 (`tests/drift.mjs`) |
| Lead by the schedule's quantum, not by the measured gap | the pair has to bracket the present, which means building about one rebuild interval ahead -- and the interval to use is the schedule's own quantum `1/(setSeconds*hz)`, which is exact, not the smoothed measured gap, which is an average of an irregular series and so is too large about half the time. Each of those asks for a negative fraction: with the floor at -0.5 and then -1.5, **9 and then 5 slot-frames sat exactly on it**, every one a jump of 9x to 26x. The quantum cannot do that, because no gap is shorter than it (`tests/drift.mjs`, `tests/secant.mjs`) |
| A bound that binds is a bug, not a safety net | both blend bounds exist for a real fault -- extrapolation drove sigma0 to -0.0204 -- but reaching one means the shape is frozen at a fraction, and releasing it is a step. Asserted at zero rather than merely bounded: **0 of 12,960 slot-frames pinned** (`tests/secant.mjs`) |
| Linear is enough, because the spline is one level up | the path between map sets is Catmull-Rom; the read-time blend is a plain secant through the two most recent builds, evaluated at the parameter the morph is at. Against an exact build at that same parameter, over 12,960 slot-frames: max abs table error **4.2e-5** at p50 and 1.4e-4 at p99, against **6.0e-3** for drawing the newest build alone -- 0.039 of one frame's own movement, and 0.045% of the entry at its very worst. **99.2%** of slot-frames now interpolate rather than extrapolate, which is where a straight line is at its best: moving the pair to bracket the present cut the tail by a factor of 40 with no change to the arithmetic. A spline would need a third sample, hence a third resident table and a third set of hot-loop reads, to improve on that (`tests/secant.mjs`) |
| The mask and the table it indexes are one object | the pool sizes a slot's jitter table by on-screen importance in its ranking pass, and the rebuild that fills the table is budgeted, so the two are not the same frame. Growing the mask on its own makes the traversal read entries above what the last build wrote -- another build of that slot, seconds of morph ago -- on whichever object had *just* become the most important one on screen: of 150 resizes over 60 s, **11 to 47** were drawn that way for one or two frames, the spread being how busy the machine was. `setTableBits` records the size wanted and the next rebuild applies it; the saving was never in the mask (`tests/breath.mjs` §6) |
| **Against every measurement of the morph above:** the dial that made it affordable was the largest jump in it | a node picks its rotation with `hash & tableMask`, so re-cutting a slot's jitter table re-draws the branch jitter of every node whose index moves -- a different realisation of the same set, in one frame, 140 to 150 times a minute, on whichever object had just become the most important one on screen. Measured as positions over a 1500-frame flight: the median step on a resize frame was **9.75e-3 of the object's radius against 5.0e-4** for an ordinary one and the worst was **4.28e-2 -- 86x the median, 16x the p99**, and every one of the fourteen largest steps in the flight was a resize. Ramped over four rebuilds instead of switched, the worst step in the same flight is **2.66e-3**, which is 1.03x the p99 of an ordinary frame, and mid-resize frames step *less* than ordinary ones (p99 2.04e-3 against 2.59e-3). A rebuild with a ramp in flight costs what a settled rebuild at the larger size costs, 0.507 ms either way (`tests/drift.mjs` §2) |
| A ratio cannot see a jump that moves the reference too | both tests that measure the drawn table compare it against an exact build **at the same mask**, so the reference re-drew its jitter in the same frame and in the same way: the error read 1.5e-5 while the picture snapped, and the step was asserted as a ratio against the true motion, which was equally large, so it read 1.00x and passed. The check that was missing is absolute -- the worst step in the flight against the distribution of ordinary frames -- and it is red at 86x with the ramp switched off (`tests/drift.mjs`) |
| **Rejected:** hysteresis on the ranking | table sizes come from rank, so two objects of nearly equal importance trading places re-cut both tables although neither changed on screen -- which looked like most of the churn. A two-place dead band turned **137 resizes over 60 s into 142**: rank drifts steadily through all eight positions as the camera flies, so a dead band delays a re-cut rather than preventing it. Not shipped (`tests/breath.mjs` §6) |
| It has to extrapolate, not lag | blending from the previous build to the newest over the gap between them holds the shape still whenever the next rebuild is late, which a budget-driven schedule makes routine: 24 Hz against 60. The fraction is a parameter position and is allowed to exceed 1 |
| **Against IDEAS.md:** arcing out of the dive is not free | 37.6% washed-out frames against 30.5% over 200 s, and the *following* dive washes 41.0% against 31.6% — the arc leaves the camera off to one side of everything. `Autopilot.arc` is 0. **Weak evidence, and it is worth saying so:** the autopilot took `Math.random`, so those were two *different* flights of a chaotic system, not one flight flown twice. `tests/legible.mjs` takes a seed now, and the paired re-run is in [STATUS.md](STATUS.md) |
| A field's representation is part of its type | `_bt` initialised to `1` rather than `0.5` cost 15 ms a rebuild instead of 2.4 for the first six rebuilds: V8 takes the representation from the first value stored, and the later fraction transitioned the hidden class and threw away the optimised `reparam`. Caught by a check that bounds the first four frames in milliseconds rather than as a ratio to the median (`tests/field.mjs`) |
